*xim.txt*	Native non-modal terminal editing
					Last change: 2026 Oct 27

Xim's native input layer uses the existing Vim text engine.  This document
describes the native editing and project workflow.

==============================================================================
1. Starting Xim						*xim-start*

Run `xim file.txt` to open a file and type immediately.  Escape cancels a
prompt or selection.  It does not switch to Vim Normal mode.

Native startup does not load your vimrc, gvimrc, plugins, or viminfo.  To load
a configuration explicitly, use `xim -u path/to/config.vim`.  There is no
implicit Xim configuration file in this milestone.  Native defaults are set
before explicit configuration and --cmd arguments.

The build stages its matching runtime alongside the executable.  An installed
build uses share/xim/runtime relative to its installation prefix.  A nonempty
VIMRUNTIME environment variable overrides runtime discovery.

Use `xim --vim` or the `vim` executable for the inherited modal interface.
Ex-mode and silent script invocations use the inherited dispatch path.

==============================================================================
2. Editing							*xim-keys*

Printable keys insert text.  Enter inserts a newline; Tab inserts a tab.
Backspace and Delete remove text and join lines at a line boundary.  Arrow
keys move by characters or logical lines.  Home/End move to the start/end of
the current line.  PageUp/PageDown scroll a page.  Wrapped-line movement
remains logical-line movement.

Shift plus an arrow, Home, or End extends an exclusive selection.  Typing
replaces the selection.  Escape cancels selection without moving the cursor.
Ctrl-A selects the buffer.  Selection is characterwise, including newlines.

The palette filters command names by case-insensitive substring.  Up/Down
move the selection in every list prompt (palette, quick open, explorer,
buffers); Enter runs or opens it.  The list scrolls to keep the selection in
view.  Open, Save as, Find and Replace accept text at the bottom of the screen.
Enter accepts; Escape cancels.  Find and Replace use literal text, so a query
never acts as a regular expression.

Find highlights every literal match as the query is typed and does not move
the caret until you navigate.  Enter goes to the next match, Shift-Enter to
the previous; F3 and Shift-F3 do the same while the prompt stays open, and
they keep working after the prompt closes.  F10 opens the menu bar even while
a prompt is open.  Escape closes the prompt and clears the highlight in the
window that owns it.  Case is smart by default: the query is case-insensitive
until it contains an uppercase letter.  Buffer matching folds case through
the editor's Unicode rules, so a long s matches s and folded pairs of
different byte length replace correctly.  Alt-C cycles smart, insensitive and
sensitive, and the active rule and the match count show at the right of the
prompt line.  A terminal that reports modifiers, such as modifyOtherKeys,
delivers Alt-C distinctly; a bare Escape followed by c is also accepted.
The native highlight is window-local match state; it never changes 'hlsearch',
so the compatibility path is unaffected.

Replace opens two fields on one line.  Tab and Shift-Tab move between the find
and replace fields.  Enter replaces every match in one undo block; Ctrl-R
replaces the current match and advances to the next.  A replacement pasted
with newlines splits into real lines, like ":s" with a line break, and one
undo restores the whole change.  A read-only or non-modifiable buffer refuses
the change and the prompt shows "read-only".

Files
								*xim-files*
Quick open lists the indexed files of the project root.  The root is the
directory argument, or the working directory for a bare start.  A file
argument opens that file alone: no index runs, and other files stay
reachable by typing an absolute path into the picker.  The root does not
change implicitly, and an out-of-root file never starts a wider scan.
Version-control internals, 'build' directories and 'node_modules' are
excluded.  Results show project-relative paths, so duplicate basenames stay
distinct.  Matching is case-insensitive; an exact basename match ranks first,
then a basename prefix, then a path substring.  Only paths are indexed, never
file contents.  The initial project buffer is scratch text, not a writable
directory.  Its first Save opens Save as.  The project directory belongs in
Recent folders, not Recent files.

A query containing a slash is treated as a path: the picker checks the
filesystem directly and offers the file even before the index arrives, and
out-of-root results show an absolute path.

Enumeration, path matching and project content search run on background
workers.  Directory pages use separate worker-owned records, so expanding a
directory never walks the whole tree or blocks typing.  The picker shows
"Indexing project..." until the snapshot arrives, or "Finding files..." while
a query is pending.  Completed results appear without another keypress.  Only
the latest query is shown; Enter during matching waits for that query, and
subsequent typing or paste belongs to the opened file.  Escape cancels a
pending choice.  Results stay capped at 200.

A Linux inotify watcher keeps the index and the explorer current after
external changes.  New, changed, renamed and deleted entries appear without a
keypress; a content change invalidates completed project-search results.  The
watcher also covers the parent directories of explicitly opened files.  The
explorer status area reports "Watcher unavailable" or "Watcher partial" with
the cause, and a network filesystem can omit events even when a watch
succeeds.  Overflow or an uncertain state requests one reconciliation scan.
Refresh project retries watch setup, rebuilds the index, keeps explorer
expansion and cancels obsolete work without waiting for the previous walk.
Changes to an existing .gitignore also update the file set.  Pending
reconciliation prevents activation of obsolete file or content results.

The explorer shows worker-owned directory pages of at most 200 entries.
Directories come before files in lexical order, empty directories are listed,
and a Load more row requests the next page, so every entry remains reachable
beyond the first page and the old 500-row limit.  Enter expands or collapses a
directory and opens a file.  Directory symlinks are never expanded, so a link
cannot lead outside the root or loop; a file symlink is listed under its own
name and opens its target.  Picking a file or buffer switches to it without a
Save/Discard prompt and keeps any unsaved buffer in the buffer list.  Buffer
rows show a stable number, '*' for the active buffer and '+' for unsaved
changes.  Buffer switches retain the last cursor column: 'startofline' is off
by default in native mode.  Rows carry their own path identity, not indentation,
and control characters are escaped.  Long paths are shortened in the middle so the
filename stays visible.  Two unnamed buffers remain separate choices.

Project search
								*xim-search*
Search project finds literal text in the indexed files.  It reuses the smart
case rule and the Alt-C toggle.  Results list each file as a header with its
matched lines beneath; Enter or a click opens the file at that match, and the
wheel moves the row selection while the results are open.  Enter pressed
while the search is still running opens the first result as soon as it
arrives, and keys typed meanwhile land in the opened buffer.  Each result
shows a bounded excerpt around the match, so a very long line cannot stall
the editor; the true match column is kept for the jump.  The search runs on a
third background worker over the file index.  Its case folding covers ASCII
and Latin-1; other scripts compare case-sensitively there, while buffer find
uses the full Unicode rules.  Files larger than 1 MiB and binary files (a NUL
byte in the first block) are skipped; the count of skipped files is reported
once as a summary line, not per file.  Results start capped at 1000 matches
or 200 files, whichever comes first, and report truncation.  Only the latest
query is searched; obsolete work is cancelled through a generation check, and
a project refresh invalidates completed results until the new scan publishes.
A file argument opens a single buffer and disables the project, so project
search is available only for a directory or a bare start.

Content search reads the on-disk text of indexed files.  Unsaved buffer
changes are not searched; save the buffer first to search the edited text.

External changes
								*xim-external*
A disk change to an open, clean UTF-8 file of at most 256 KiB reloads
automatically.  The staged bytes are applied only while the buffer, its edit
revision and the disk identity still match the observation that started the
read; typing during the read turns the completion into a conflict.  The reload
keeps the caret position and leaves one undo step back to the previous text.
It also updates the disk timestamp and the 'fileformat', 'endofline' and
'bomb' values.  The 'fixeol' option still controls final newlines on write.
Invalid UTF-8, larger files, binary files and hidden buffers are not reloaded
automatically.  A dirty buffer keeps its edits.

The status line shows "[!] changed on disk" or "[!] missing on disk" for the
active buffer.  File > Changed files lists every pending notice.  File >
Reload from disk applies the disk text; on a dirty buffer it requires [r]
consent, because that discards local edits.  File > Keep edits accepts the
current text as the new base without writing it, so a later save still uses
the engine's overwrite checks.  File > Check external changes re-observes
tracked files without waiting for the watcher.  An external deletion keeps the
buffer text, marks it modified and shows it as missing.  Save asks "Recreate?".
Choose [s] Recreate to write the missing file, or Escape to cancel.  Save during
Close or Quit also requires this choice for missing hidden buffers.  An unambiguous external rename updates the buffer path; an
ambiguous move only marks the old path missing.  A directory move checks the
identity of each open descendant before changing its buffer path.  Directory
deletion also protects open descendants, including hidden buffers.
Autocommands from a reload
run on the owning thread.

File operations
							*xim-file-operations*
File > New file, New folder, Rename, Move and Delete permanently use the
explorer selection, or the active document when it belongs to the project.  A
right-click on an explorer row opens the same actions for that row.  Names and
Move destinations are relative to the project root.  New file creates an
empty disk file and opens it without closing the current buffer or prompting
about its unsaved edits.  New file and New folder accept a relative path only
when its parents exist.  Rename does not accept path separators.  Move
requires an existing destination parent and refuses a folder's own descendant.
Existing destinations are errors: no action overwrites, merges or silently
truncates a file, directory or distinct open buffer.  A move across
filesystems fails visibly and leaves the source intact.

Delete permanently operates on files and nonempty directories.  Its
confirmation shows the exact target, a worker-summarized entry count and the
number of affected dirty buffers, and Delete must be chosen explicitly.
Symlinks are unlinked, never followed.  A recursive delete can fail after
partial progress; the result reports what remains instead of claiming
rollback.  Deleted buffers are not closed or discarded: their text stays
available, marked modified and missing on disk, so Close and Quit protect even
a previously clean in-memory copy.  Filesystem changes are not covered by
buffer undo; Ctrl-Z cannot recover a deleted disk entry.  Trash, filesystem
undo and recursive copy are not provided.

Preflight and mutation run on a serialized worker.  Only one namespace change
runs at a time; a conflicting request reports Busy.  Rename and Move preserve
dirty text, modified flags, undo history and window identity, and they update
every affected buffer path, including descendants of a moved directory.
Failures keep the prompt input and report the actual cause.  Project switching
and Quit wait for an unresolved mutation instead of abandoning a committed
disk change.

Recent files and projects
								*xim-recent*
File > Recent files and Recent folders list successful opens, saves and
project selections.  Entries are absolute, deduplicated and shown relative to
the current project when possible.  They persist in
$XDG_STATE_HOME/xim/recent.json, or $HOME/.local/state/xim/recent.json when
XDG_STATE_HOME is unset, empty or relative.  The state file is data, not
Vimscript.  Reads and writes run off-thread; writes are atomic, the state
directory is mode 0700 and the file mode 0600, and instances merge under a
file lock.  Each writer applies its new actions to the latest disk state, so
another instance's removals or Clear do not reappear from an old cached list.
The lists hold at most 100 files, 20 folders and 256 KiB of state data.
A missing entry reports its path and can be removed from the list.
File > Clear recent history deletes the lists.  Malformed paths and JSON are
not opened as filenames.  An unsupported state version is left unchanged.
Persistence errors appear in the recent picker; a later history action retries
pending changes.  A held file lock cannot indefinitely delay Quit.

File > Open folder validates a directory off-thread and keeps the current
project unchanged if validation fails.  File > Close project stops indexing,
content search and project watching but keeps open buffers, explicit-file
watches and recents.  Switching projects preserves named, unnamed and dirty
buffers, including files outside the new root, and cancels old picker
continuations before the root changes.  Explorer expansion restarts from the
new root; the status line reports the project name.

Save on an unnamed buffer opens Save as.  The explicit Open prompt, Close,
and Quit protect modified buffers with Save, Discard, and Cancel choices.
Quit checks all buffers, including buffers kept unsaved by a picker switch.
Failed writes retain the modified text and report the error.  A
failed confirmation save keeps Save, Discard, and Cancel available.  Save as
refuses to overwrite an existing file; an explicitly requested Ex command
can apply the inherited write policy.  A successful Save or Save-as write
keeps the cursor at its previous insertion point.  An empty or failed Save-as
choice does not revive a cancelled pending operation.

Typing is grouped into undo entries of at most 256 characters.  Newlines,
movement and commands end a typing group.  Paste and selection replacement
have a single undo boundary.  Bracketed paste retains literal tabs, newlines,
and text without applying mappings or indentation rules.

3. Terminal and clipboard support				*xim-terminal*

The tested native target is Linux with UTF-8 and xterm-compatible terminal
key sequences, including xterm-256color and bracketed paste.  The existing
decoder handles supported terminal protocols; native dispatch receives its
decoded characters, special keys, and Shift/Ctrl/Alt modifiers.

Xim disables terminal Ctrl-S/Ctrl-Q flow control in native raw mode.  A
terminal or multiplexer can still intercept shortcuts before Xim receives
them.  Ctrl-Shift-S is indistinguishable from Ctrl-S on many terminals; use
the palette in that case.  Unrecognized keys are ignored.  Alt-letter menu
access works where the terminal distinguishes Alt; the mouse remains the
primary menu pointer.  Platform-specific GUI input and operating-system
gestures are outside the editor's reporting boundary.

The top row shows File, Edit, View, Navigate and Help.  F10 opens the
menu; Left/Right switch headings, Up/Down move, Enter runs, Escape
dismisses.  Opening a heading selects its first entry, so Enter runs it
without a Down first.  Click a heading to open it, hover to switch while
open, and click or press-drag-release an entry to run it.  Clicking outside
dismisses.  Narrow terminals clip trailing headings; keyboard access still
reaches every group.  Right-click opens Edit choices at the pointer
without clearing the selection.  Help > Xim help opens this doc.  F10 was
the Redo fallback; use Ctrl-Y for Redo.  Ctrl-N creates a new buffer; use
F3 for Next match.

Mouse reporting uses inherited SGR sequences and is enabled by default in
native mode.  Click places the insertion point; Shift-click extends the
selection; drag selects; double-click selects a word; triple-click
selects a logical line.  The wheel scrolls the window under the pointer
and never moves the caret or selection; typing brings the caret back into
view.  Middle-click pastes through the clipboard boundary.  Dragging a
window's status line or vertical separator resizes the split.  Picker rows,
the confirmation Save/Discard/Cancel labels and prompt input accept clicks;
the wheel moves list selection.  Prompts support Left/Right, Home/End,
Delete, Select all, clipboard and mouse placement.  Motion reporting is
active only while a menu is open.

Copy and cut require a selection.  Xim keeps an internal text clipboard when
the inherited '+' clipboard is unavailable.  When '+' is available, Xim uses
the engine's configured X11 or Wayland clipboard path.  Native startup does
not load a clipboard-provider plugin.  No new OSC 52 transport is provided.
Copy uses register x as an engine scratch register.  NUL-containing binary
clipboard/paste payloads are not part of the native text-input contract.

==============================================================================
4. Themes and scripting					*xim-compatibility*

Vimscript evaluation, buffer APIs, Ex commands and Vim colorschemes remain
available.  Choose Ex command in the palette to enter an Ex command without
leaving native editing.  Explicit -u files and --cmd/-c commands can set
options, define functions and autocommands, or load a colorscheme.

Native selection reuses Visual highlighting.  The native interface defines
these default links, which follow a colorscheme's target groups: >vim
	hi default link XimStatus StatusLine
	hi default link XimPrompt Pmenu
	hi default link XimPalette Pmenu
	hi default link XimPaletteSel PmenuSel
	hi default link XimMenuBar StatusLine
	hi default link XimMenuSel PmenuSel
<
Users can override these groups.  Shipped themes tested include default,
desert, slate, habamax and catppuccin.  Two local third-party Phi themes,
phi_canary and phi_copper, were tested with 'termguicolors'.  This sample
does not establish support for every Vim or Neovim theme.

The native layer uses Insert state for engine cursor bounds, but it does
not run the inherited edit() loop.  Modal mappings, abbreviation/completion
hooks, InsertEnter/InsertLeave, TextChangedI and CursorMovedI behavior are
not guaranteed.  The top-level loop still sends deferred TextChanged and
CursorMoved events.  Plugins that rely on modal UI state need compatibility
mode.  Ex commands that open inherited modal UI are best-effort interfaces.

Editor-state mutation stays on the main thread.  The command/input boundary
does not expose Vim globals to future background workers.
